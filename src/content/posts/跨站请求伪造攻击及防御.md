### **一、什么是跨站请求伪造漏洞？**

#### 1. **🚩定义与原理**


*   **跨站请求伪造（CSRF）** 是一种攻击方式，攻击者通过诱导用户在已登录的网站上执行非预期操作。  
    **核心原理**：利用浏览器自动携带目标网站 Cookie（或其他身份凭证）的机制，伪装成合法用户发起恶意请求。

#### 2. **攻击场景举例**


*   **场景 1：银行转账**  
    用户已登录网银（`bank.com`），访问恶意网站（`malicious.com`），后者偷偷嵌入以下代码：
    ```html
    <img src="https://bank.com/transfer?to=attacker&amount=1000" style="display:none">
    ``` 
    恶意网站的这段代码会向网银发送一个请求，使得其认为事本人发起的操作。
    浏览器会自动携带 `bank.com` 的 Cookie 发起请求，若银行未验证请求来源，资金将被转移。
    
*   **场景 2：修改邮箱（CSRF 表单）**  
    恶意网站创建隐藏表单，诱导用户点击按钮：
    ```html
    <form action="https://example.com/account/change_email" method="POST" id="csrf-form">
      <input type="hidden" name="email" value="attacker@malicious.com">
    </form>
    <button onclick="document.getElementById('csrf-form').submit()">点击领取奖品！</button>
    ```

#### 3. **CSRF 与 XSS 的区别**

*   **XSS**：攻击者通过注入恶意脚本，获取用户信息或控制用户行为，重点在 "窃取信息"；
*   **CSRF**：攻击者利用用户已有的身份，让浏览器 "替用户" 发送请求，重点在 "伪造操作"。


### **🎃二、CSRF 漏洞的特点**

#### 1. **攻击条件**


*   用户已登录目标网站（持有有效会话）。
*   目标网站未实施有效的 CSRF 防护机制。

#### 2. **常见利用方式**


*   **GET 请求攻击**：通过 `<img>`、`<script>` 等标签触发（如场景 1）。
*   **POST 请求攻击**：通过隐藏表单或 AJAX（需同源策略绕过）。
*   **JSON 请求**：部分浏览器允许跨域发送 JSON 请求（需配合 CORS 漏洞）。

#### 3. **防御难点**


*   攻击者无需获取用户 Cookie，仅需利用浏览器自动携带的凭证。
*   难以区分合法请求与 CSRF 请求（均来自用户浏览器）。

### **三、CSRF 漏洞检测与利用**

#### 1. **手工检测方法**


*   **步骤 1：识别敏感操作**  
    如修改密码、转账等接口（通常为 POST 请求）。
    
*   **步骤 2：构造 CSRF POC**  
    编写 HTML 页面，模拟用户请求：
    
    ```html
    <form action="https://target.com/change_password" method="POST">
      <input type="hidden" name="old_password" value="current">
      <input type="hidden" name="new_password" value="hacked">
    </form>
    <script>document.forms[0].submit();</script>
    ```
    
      
    
*   **步骤 3：诱使用户访问**  
    若用户在已登录状态下访问该页面，密码将被修改。
    

#### 2. **自动化工具**


*   **OWASP ZAP**：内置 CSRF 扫描器，可检测漏洞并生成 POC。
*   **Burp Suite**：通过 Repeater 模块构造并测试 CSRF 攻击。

### **四、CSRF 防御策略**

#### 1. **使用 CSRF Token**


*   **原理**：服务器为每个用户会话生成唯一 Token，表单或请求中必须包含该 Token 才能生效。
*   **实现示例（Python + Flask）**：
    ```python
    # 生成 Token
    import os
    session['csrf_token'] = os.urandom(16).hex()
    
    # 渲染表单时嵌入 Token
    <input type="hidden" name="csrf_token" value="{{ session.csrf_token }}">
    
    # 验证 Token
    if request.form['csrf_token'] != session['csrf_token']:
        abort(403)
    ```
    
      
    

#### 2. **SameSite Cookie 属性**


*   **设置 Cookie 时添加 `SameSite` 标记**：
    
    *   `SameSite=Strict`：完全禁止第三方请求携带 Cookie。
    *   `SameSite=Lax`：允许部分安全的跨站请求（如链接跳转）。
    *   `SameSite=None`：需配合 `Secure` 属性，仅在 HTTPS 下允许跨站携带。
    
    ```python
    # Flask 示例
    response.set_cookie('session_id', value, samesite='Lax')
    ```
    
      
    

#### 3. **验证请求来源（Referer/Origin）**


*   **检查请求头中的 `Referer` 或 `Origin`**：
    
    ```python
    # Flask 示例
    from flask import request
    
    def validate_referer():
        referer = request.headers.get('Referer')
        if referer and not referer.startswith('https://target.com'):
            abort(403)
    ```
    
      
    

#### 4. **避免使用 GET 请求处理敏感操作**


*   将敏感操作（如删除、修改）改为 POST/PUT/DELETE 请求。

#### 5. **验证码机制**


*   关键操作（如密码修改、支付）强制用户输入验证码。

### **五、实战案例分析**

#### 案例：某论坛 CSRF 漏洞导致用户信息泄露

1.  **漏洞发现**：  
    修改个人资料接口（`/user/update_info`）未验证 CSRF Token。
    
2.  **攻击构造**：
    
    ```html
    <form action="https://forum.example.com/user/update_info" method="POST">
      <input type="hidden" name="email" value="attacker@example.com">
      <input type="hidden" name="phone" value="123456789">
    </form>
    <script>document.forms[0].submit();</script>
    ```
    
      
    
3.  **修复方案**：
    
    *   后端添加 CSRF Token 验证。
    *   设置 `SameSite=Lax` 保护会话 Cookie。
